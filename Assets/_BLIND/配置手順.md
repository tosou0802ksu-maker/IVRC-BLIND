# BLIND ギミック配置手順（ワールド班向け）

計画書(Excalidraw)の仕様に対応するスクリプトは全部書いてある。
シーンへの配置はこの手順どおりにInspectorを繋ぐだけで動く。

---

## 0. レイヤーと「3つの世界」の考え方（最重要）

| index | 名前 | 誰に見えるか |
|---|---|---|
| 0 | Default | **過去の人だけ** |
| 22 | Thermal | **サーモ役だけ** |
| 23 | Echo | **エコロケ役だけ** |
| 24 | Memory | 過去の人だけ（看板・矢印・クイズの文字・偽ボタンの色） |

**ここが一番大事なところ:**

エコロケ役とサーモ役には **Defaultレイヤーの物は一切見えない**。視界は真っ黒。
つまり「壁も床も全員に共通で見える」わけではなく、**役割ごとに別々の世界を用意する**構成になっている。

同じ1つの物（例えば箱）を3人全員に見せたいなら、**見た目のメッシュを3つ重ねて置く**。

```
Box_Root                      ← 位置と当たり判定(Collider)はここに1つだけ
 ├ Vis_Default   (Default)    ← 普通の見た目。過去の人だけに見える
 ├ Vis_Echo      (Echo/23)    ← EchoMaterial。エコロケ役だけに見える
 └ Vis_Thermal   (Thermal/22) ← Thermalマテリアル。サーモ役だけに見える
```

### ✅ これは毎回手で組まなくてよい（プレハブ済み）

| プレハブ | 用途 | サーモでの見え方 |
|---|---|---|
| `Assets/_BLIND/Prefabs/TriRole_Block.prefab` | 壁・床・柱・障害物 | 冷たい（青〜紫） |
| `Assets/_BLIND/Prefabs/TriRole_HotBlock.prefab` | 熱源・機械・ボタン台 | 熱い（黄〜赤） |

**置いて、位置と大きさ(Scale)を変えるだけ**でよい。3視点分の見た目と`EchoReceiver`は最初から入っている。
形を変えたい時は中の3つの子メッシュを同じように差し替える（3つとも必ず同じ形・同じ位置にする）。

### ⚠️ 配置し終わったら必ずこれを実行

メニューバー **[BLIND] → [エコロケ受信機を集め直す]**

`EchoEmitter` は「パルスを届ける相手」のリストを持っていて、**このリストに載っていない物はエコロケ役に永遠に見えない**。
ブロックを置き終わったらこのメニューを1回押せば、シーン内の全部が自動で登録される。押したらシーンを保存する。

### 床タイルについて

p1の床タイルは7,674枚あるので、**1枚ずつEcho用に複製しない**こと。
エコロケの見た目は「輪郭が光る」だけなので、部屋ごとに**大きな板を1枚**`TriRole_Block`で置けば十分で、
そのほうが軽くて見た目もきれいになる。

※ 逆に「この役割にだけ見せたくない」ものは、その役割用のメッシュを作らなければよい。
　 落とし穴をエコロケだけに見せる／熱源をサーモだけに見せる、といった情報格差はこれで作る。

## 1. PlayerVisionController（役割別の見え方）

`Main_Camera` にアタッチ済み。**設定済みなので基本さわらなくてよい。**

| フィールド | チェックするレイヤー | 背景 |
|---|---|---|
| echoCullingMask | Echo のみ | 真っ黒 |
| thermalCullingMask | Thermal のみ | 真っ黒 |
| memoryCullingMask | Default, Memory, Player, PlayerLocal | 通常(スカイボックス) |

`echoBlackout` / `thermalBlackout` がオンだと、スカイボックスを描かず真っ黒で塗りつぶす。
これで「暗闇の中に光る輪郭だけが浮かぶ」という見え方になる。

Echo/Thermalで **Player を外している** のが重要。他人の実アバターが消えて、代わりに
`RemotePlayerProxyManager` が出すマネキン(輪郭／熱源)が見える、という作りになっている。

※ VRChat実機ではシーンのCameraではなく `VRCCameraSettings.ScreenCamera` を書き換える実装。
　 `localCamera` はエディタ確認用なので未設定でよい。

## 1.2. EchoMaterial（輪郭の光り方）

`Assets/_BLIND/Art/Materials/EchoMaterial.mat`（シェーダー: `BLIND/EchoHighlight`）

エコロケ用メッシュにはこのマテリアルを使う。物体の面は真っ黒のまま、**UVの端（面の輪郭）だけが光る**。
パルスが当たっていない時は完全に真っ黒で見えない。

| プロパティ | 意味 |
|---|---|
| Edge Color | 輪郭の色（初期値は緑。白にしたければここを白に） |
| Edge Thickness | 輪郭線の太さ |
| Edge Intensity | 輪郭の明るさ |
| Glow Intensity | **さわらない。** `EchoReceiver` が0→1で自動制御する |

## 1.5. RemotePlayerProxyManager + HumanoidProxyRig（他プレイヤーの見え方）

PlayerVisionControllerでPlayerレイヤーを外しただけだと、Echo/Thermal役には**他プレイヤーが何も見えなくなる**。
代わりに主要な関節を追従する「人型プロキシ」を表示させることで、
「エコロケなら人型のシルエット」「サーマルなら人型の熱源」として相手の姿・ポーズが分かるようにする
(球体1個が浮いているだけではなく、しゃがむ/手を伸ばす等のポーズも再現される)。

### A. プレハブは作成済み(`Assets/_BLIND/Prefabs/HumanoidProxyRig.prefab`)

胴体・首・頭・両腕(上腕/前腕)・両脚(腿/すね) = 11パーツで構成済み。各パーツにEcho(23)用の輪郭メッシュとThermal(22)用の熱メッシュ(`ThermalHeat_Proxy.mat`)が重ねてあり、`HumanoidProxyRig`コンポーネントの配線(`torso`〜`rightShin`、`thermalRenderers`)も完了している。
太さ・見た目の微調整だけデザイン側で詰めてもらえればOK(位置・回転・長さは全部スクリプトが毎フレーム自動計算するので触らなくてよい)。

MainWorldシーンの `GameManagement` 以下に `Proxy_Slot0` / `Proxy_Slot1` として既に2体配置・`RemotePlayerProxyManager` への配線も完了済み。
p1マップ側でも同じプレハブを好きな場所に2体置いて `RemotePlayerProxyManager.proxyRigs` に入れれば動く。

### B. シーンに配置(p1側で使う場合)

1. `HumanoidProxyRig.prefab` を**自分以外の人数分**(最大2つ)シーンに置く
2. 空のGameObjectに `RemotePlayerProxyManager` をアタッチ(ワールドに常時1つ)
3. `proxyRigs` に配置したプレハブインスタンスを順番に入れる
4. `remotePlayerHeat` は熱の強さ(0〜1くらいで調整)

これで他プレイヤーの主要ボーン位置(頭/胸/腰/肩/肘/手/腰/膝/足)に毎フレーム自動で追従し、Echo役には輪郭だけ、Thermal役には熱だけが人型ポーズ付きで見える状態になる。
Memoryロールは元々Playerレイヤーを含めているので、他プレイヤーの実アバターがそのまま見える（プロキシは不要）。

## 2. CheckpointManager（セーブポイント）

空のGameObjectにアタッチ。

- `checkpoints[0]` = スタート地点のTransform
- `checkpoints[1]` = 赤ボタンの部屋
- `checkpoints[2]` = 青ボタンの部屋（レーザー）
- `checkpoints[3]` = 緑ボタンの部屋（最後の部屋）
- `doors` = 後述のToggleDoorを全部入れる

誰か1人が罠に触れると **全員** がここに戻る。

---

## 3. 赤・青・緑ボタン

**ShuffleSequenceManager**（空オブジェクト1個、マップに1つだけ）
- `shuffleManager` = ViewpointShuffleManager
- `checkpointManager` = 上のCheckpointManager
- `correctOrder` = 0, 1, 2（赤→青→緑）

**ShuffleButton**（ボタン3個それぞれに）
- `sequenceManager` = 上のShuffleSequenceManager
- `buttonId` = 赤:0 / 青:1 / 緑:2

押すと **視点シャッフル + セーブポイント登録 + 扉の開閉** が同時に起きる。

---

## 4. ToggleDoor（赤開く／赤閉じるドア）

扉ごとにアタッチ。

- `checkpointManager` = CheckpointManager
- `requiredCheckpoint` = 赤:1 / 青:2 / 緑:3
- `openWhenReached` = 「◯開くドア」なら **true** / 「◯閉じるドア」なら **false**
- `doorBody` = 閉じている時に置いておく板（Colliderつき）。開くとSetActive(false)される

状態は同期済みの `currentIndex` から計算するので、途中参加でもズレない。

---

## 5. QuizManager / QuizChoiceButton（クイズ部屋）

- `correctChoice` = 正解の選択肢番号（0始まり）
- `doorBody` = 正解で開く扉
- `trapFloor` = 不正解で消える床。**その下に落とし穴のHazardZoneを置く**
- `checkpointManager` = 床を使わず即セーブポイントに戻す場合のみ設定

選択肢ボタンごとに `QuizChoiceButton` を付けて `choiceIndex` を 0,1,2... と振る。
**問題文と選択肢のラベルはMemoryレイヤーに置く**（過去の人しか読めない）。

不正解後は再挑戦できる（ペナルティは落下と巻き戻しのみ）。完全に一回きりにすると詰むため。

---

## 6. PressurePlate / PressurePlateDoor（2つ踏むと開くドア）

**PressurePlate**（板ごと、IsTriggerのColliderが必要）
- `door` = 対応するPressurePlateDoor
- 板の見た目は **Echoレイヤー**（エコロケだけが形として認識できる）

**PressurePlateDoor**
- `plates` = 対応する板を全部
- `requiredCount` = 2
- `doorBody` = 扉の実体
- `stayOpen` = オフ推奨（降りたら閉まる。2人が踏み続けて1人が進む形になる）

同期変数を使っていないので設定漏れの心配はない。

---

## 7. HazardZone（落とし穴・レーザー）

- `checkpointManager` = CheckpointManager
- `thermalWarning` = DynamicThermalObject（サーモ役への警告表示）
- レーザーのように点滅させるなら `activeDuration` / `inactiveDuration` を設定
