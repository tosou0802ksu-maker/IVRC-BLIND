# BLIND ギミック配置手順（ワールド班向け）

計画書(Excalidraw)の仕様に対応するスクリプトは全部書いてある。
シーンへの配置はこの手順どおりにInspectorを繋ぐだけで動く。

## 0.5. RoomBuilder3の不具合修正について(p1の21部屋に影響・重要)

Excalidrawの「現在の問題点」に挙がっていた6件は、p1の全21部屋が使っている
`Assets/_BLIND/Scenes/RoomBuilder3.cs` 側のバグと判明したため、**スクリプト側を直接修正した**。
1ファイルなので21部屋すべてに自動で反映される(部屋ごとの個別修正は不要)。Unity上で該当オブジェクトを
選択し直す(Inspectorを触ってOnValidateを走らせる)か、Playすれば新しいコードで再生成される。

| 問題 | 原因 | 対応 |
|---|---|---|
| 扉の下に床が生成されない | 床が部屋の内寸ぴったりで、壁の厚みの外側半分に床が無かった | 床を壁の厚み分外側まで拡張 |
| 扉を潜るときに壁紙の境目が見える | 入り口がある壁だけ部屋の角まで届かず、四隅に隙間が空いていた | 壁を必ず部屋の角(隣の壁の中心線)まで伸ばすよう修正 |
| 扉の枠部分が重なってる | 柱が下枠・上枠と同じ高さ範囲を奪い合っていた(Zファイティング) | 「下枠→柱→上枠」を縦に隙間なく積む構造に変更 |
| 北と南だけ床と壁のタイルの線が合わない | 上記の床拡張漏れによる非対称なズレ | 床拡張の修正で解消 |
| テクスチャを壁に貼った時、模様の縦横比率が変わる | オブジェクトのサイズに応じてUVが引き伸ばされていた | 下記の`BLIND/RoomSurface`シェーダーで解決(実寸貼り) |
| テクスチャを貼ると本来の色より暗い色になる | 密閉部屋は環境光がほぼ無くPBRで暗く落ちる | 同シェーダーの`Ambient Boost`で明るさを底上げ |

### 新シェーダー `BLIND/RoomSurface`(床・壁・天井専用)

`Assets/_BLIND/Scripts/RoomSurface.shader`。UVを一切使わず**ワールド座標から直接テクスチャを貼る
トライプラナー方式**なので、部屋のサイズや壁の向きに関係なく模様が実寸(メートル単位)で揃う。
床・壁の継ぎ目も同じ座標系を参照するため自動で一致する。

- `Texture Size (meters)` = 1で「1マス=1m」。テクスチャによって値を調整
- `Ambient Boost` = 密閉部屋での暗さ対策の自己発光量。初期値0.35、暗く感じたら上げる
- 使い方: `RoomBuilder3`の `Floor Material` / `Wall Material` / `Ceiling Material` に、このシェーダーで
  作ったマテリアルを指定するだけ(UVは自動で無視されるので今までの貼り方の心配は不要)
- サンプル: `Assets/_BLIND/Art/Materials/Room_Tiles141_White.mat`(テカリ白タイル用、そのまま複製して他の柄にも流用可)

## 0. レイヤーと「3つの世界」の考え方（最重要）

| index | 名前 | 誰に見えるか |
|---|---|---|
| 0 | Default | **過去の人だけ** |
| 22 | Thermal | **サーモ役だけ** |
| 23 | Echo | **エコロケ役だけ** |
| 24 | Memory | 過去の人だけ（看板・矢印・クイズの文字・偽ボタンの色） |

**ここが一番大事なところ:**

エコロケ役とサーモ役には **Defaultレイヤーの物は一切見えない**。視界は真っ黒。
つまり「壁も床も全員に共通で見える」わけではなく、**役割ごとに別々の世界を用意する**構成になっている。

同じ1つの物（例えば箱）を3人全員に見せたいなら、**見た目のメッシュを3つ重ねて置く**。

```
Box_Root                      ← 位置と当たり判定(Collider)はここに1つだけ
 ├ Vis_Default   (Default)    ← 普通の見た目。過去の人だけに見える
 ├ Vis_Echo      (Echo/23)    ← EchoMaterial。エコロケ役だけに見える
 └ Vis_Thermal   (Thermal/22) ← Thermalマテリアル。サーモ役だけに見える
```

### ✅ これは毎回手で組まなくてよい（プレハブ済み）

| プレハブ | 用途 | サーモでの見え方 |
|---|---|---|
| `Assets/_BLIND/Prefabs/TriRole_Block.prefab` | 壁・床・柱・障害物 | 冷たい（青〜紫） |
| `Assets/_BLIND/Prefabs/TriRole_HotBlock.prefab` | 熱源・機械・ボタン台 | 熱い（黄〜赤） |

**置いて、位置と大きさ(Scale)を変えるだけ**でよい。3視点分の見た目と`EchoReceiver`は最初から入っている。
形を変えたい時は中の3つの子メッシュを同じように差し替える（3つとも必ず同じ形・同じ位置にする）。

### ⚠️ 配置し終わったら必ずこれを実行

メニューバー **[BLIND] → [エコロケ受信機を集め直す]**

`EchoEmitter` は「パルスを届ける相手」のリストを持っていて、**このリストに載っていない物はエコロケ役に永遠に見えない**。
ブロックを置き終わったらこのメニューを1回押せば、シーン内の全部が自動で登録される。押したらシーンを保存する。

### 床タイルについて

p1の床タイルは7,674枚あるので、**1枚ずつEcho用に複製しない**こと。
エコロケの見た目は「輪郭が光る」だけなので、部屋ごとに**大きな板を1枚**`TriRole_Block`で置けば十分で、
そのほうが軽くて見た目もきれいになる。

※ 逆に「この役割にだけ見せたくない」ものは、その役割用のメッシュを作らなければよい。
　 落とし穴をエコロケだけに見せる／熱源をサーモだけに見せる、といった情報格差はこれで作る。

### チェス盤部屋の床（例外パターン）

チェス盤部屋の床も基本方針どおり**1枚の大きな板**にし、マテリアルで「床っぽく」見せる（タイル分割しない）。
ただしこの部屋だけ「エコロケでマス目の溝が見える」演出が欲しいので、Echo層の板をもう1枚重ねる。

- `Assets/_BLIND/Art/Materials/EchoChessGrid.mat`（シェーダー: `BLIND/EchoChessGrid`）
- 通常の `EchoMaterial` は板の外周だけが光るが、これは**外周＋内部のマス目線**の両方が光る
- `Grid Size` プロパティ = 1辺のマス数（チェス盤なら8）。板のUVが0〜1の1枚板であることが前提
- 使い方は他のEchoレイヤー物と同じ: 板に`EchoReceiver`を付けて`targetRenderers`に自分を入れる → `[BLIND]→[エコロケ受信機を集め直す]`を忘れずに

## 0.8. サーモ・エコロケ層の自動生成（[BLIND]→[vision] メニュー）

上の「3つ重ねて置く」を部屋ごとに手で組むのは現実的でないので、
**Defaultレイヤーの見た目から Thermal(22) と Echo(23) を自動生成するツール**を用意した。

| メニュー | 内容 |
|---|---|
| `BLIND/vision/1. サーマル材質を作り直す` | 温度ごとのマテリアルを `Art/Materials/Thermal/` に生成 |
| `BLIND/vision/2. 担当部屋にサーモ・エコロケを生成` | 部屋の下に `Vision_Thermal` / `Vision_Echo` を作る |
| `BLIND/vision/9. 生成したサーモ・エコロケ層を消す` | 作り直す前に実行 |

対象の部屋は `BlindVisionBuilder.BuildMine()` の配列で指定する。
実行後は **必ず `[BLIND]→[エコロケ受信機を集め直す]`** を押すこと。

### 何が起きるか

- 部屋の中のレンダラーを名前とマテリアル名から**温度クラスに分類**する（`BlindVisionBuilder.Classify`）
- 分類ごとにメッシュを結合して1枚にまとめる。room12 の場合 596個 → サーモ10枚・エコロケ9枚
- 重いメッシュ(260三角形超)と読み取り不可のメッシュは**箱／楕円体の簡易形状に置換**する。
  そのまま複製すると room16 だけで 58万三角形増えるため。現在6部屋合計で約10万三角形
- エコロケ層は原則**簡易形状**にする。`EchoHighlight` は「UVの端＝輪郭」で線を引くので、
  UVが0〜1でないメッシュ（床タイル・手続き生成の書架・FBXの実寸UV）だと面全体が
  輪郭と判定されてベタ塗りになる。箱と楕円体なら必ず面ごとに0〜1が入る
- 床は部屋につき**大きな板1枚**に置き換える（タイルのままだと上記の理由で潰れる）。
  水面も「そこが床の高さ」を意味するので同じ板にまとめる
- **最小辺2.5m超／最大辺5m超の大物だけは素のメッシュのまま置く**（結合しない単独レンダラー）。
  簡易形状の誤差は寸法に比例するので、room7 の巨大アヒル(8.8×7.5×8.0m)を楕円体にすると
  直径8mの球がプール室をまるごと埋め、**中に入った側からは胸から上が何も見えなくなる**。
  現在この扱いになるのは GiantDuck / PoolBasin / GiantArm の3体だけ
- 焼け跡や汚れの**デカール（decal / stain / soot）は生成しない**。床に密着したゼロ厚の面なので
  複製すると床と同じ高さに2枚重なってZファイティング（チラつき）を起こす。汚れには温度も反響も無い

### サーモとエコロケで見せる情報を分ける（重要な設計判断）

**床・壁・天井をサーモにはっきり出してはいけない。** サーモ役だけで空間の形が読めてしまい、
「エコロケ役が形を伝える」という非対称協力の前提が崩れるため。

そこで各温度クラスに `dim`（0=真っ黒 1=そのまま）を持たせている。**不透明のままなので
遮蔽は効いたまま**（壁の向こうは見えない）で、見た目だけが黒く沈む。

| 区分 | dim | 見える距離 | 意図 |
|---|---|---|---|
| 床・壁・天井 | 0.02〜0.03 | 〜5m | ほぼ黒。形はエコロケ役の領分 |
| 什器（棚・箱・小物） | 0.05〜0.09 | 5〜7m | 気配だけ。手を伸ばす距離で「何かある」と分かる程度 |
| 水・ダクト | 0.15〜0.20 | 15〜20m | 落ちると危ない／道しるべになるので例外的に読ませる |
| 熱源（蛍光灯・人・機械） | 0.85〜1.00 | 全域 | ここだけ全開。サーモ役の領分 |

**dim は2か所に効く。** 明るさそのものと、`ThermalSurface` の距離フェードの効き方の両方。
減光だけだと「近寄れば結局全部読める」ので、dim が小さい物ほど手前でしか見えないようにしてある
（`_FadeNear` 5m 〜 `_FadeFar` 200m を dim² で補間）。実機でも距離が延びるほど
温度差は背景放射に埋もれるので、理屈としても現実に沿っている。

> **注意: 色空間が Linear なので dim をそのまま掛けても暗くならない。**
> 0.05 倍にしても体感の明るさは 26% までしか落ちない（0.05^(1/2.2) ≒ 0.26）。
> シェーダー側で `pow(_Dim, 2.2)` して知覚量→リニア量に直しているので、
> **表の数字は「見た目でどのくらいの明るさか」として読んでよい。**

### 温度の設計値（`BlindThermalTable`）

実際のサーモグラフィで観測される値を基準にしている。ただし現実の室内は壁も床も棚も
17〜19℃にほぼ収まるので、**順序と理由は現実どおり、差は読めるところまで開く**方針で振ってある。

| ℃ | クラス | 根拠 |
|---|---|---|
| 11 | Water | 溜まり水。気化熱で室温より低い |
| 15 | FloorStone | コンクリ・テラゾー床。熱容量が大きく最も冷たい |
| 16 | Metal | スチール書架。金属は放射率が低く実際より冷たく写る |
| 18 | Wall | 塗装壁。室温そのもの（基準） |
| 19〜22 | Prop / Wood / Cardboard / Fabric | 断熱性が高いものほど室温より高く写る |
| 21.5 | Ceiling | 吊り天井。暖気が溜まる |
| 19 | LampOff | **切れている照明パネル。樹脂板が室温のまま** |
| 25 | Duct | 空調ダクト |
| 32 | LampDim | **調光・ちらつき中の照明パネル。生きてはいるが出力が低い** |
| 34〜36 | Body / Skin | 人体 |
| 47 | CRTOn | 通電中のCRT筐体 |
| 52 | Lamp | 蛍光管。管壁は40〜60℃ |
| **68** | **Ballast** | **照明器具の本体・安定器。蛍光灯で最も熱い部位** |
| 95 | Fire | 炎。レンジ上限で振り切れる |

表示レンジは 12〜70℃、ガンマ0.65。実機のオートレンジに近い非線形で、
室温帯の1℃差でも色が動き、蛍光灯は上で潰れる。

新シェーダー `BLIND/ThermalSurface` は **`_TempC` に摂氏をそのまま入れる**。
既存の `ThermalHeat`/`ThermalCold` は色を「カメラとの角度」から作っていたため
同じ物でも見る向きで温度が変わって見えたが、こちらは温度だけで色が決まる。
角度は「かすめる角度ほど放射率が下がって低く写る」ぶんの補正にしか使わない。

照明パネルは On / Dim / Off の3種のマテリアルを見分けて別の温度にしている。
**サーモ役には「どの列の灯りが生きているか」が読める**ので、天井の熱の並びが道しるべになる。

### チラつき（フリッカー）対策

サーマル視点で床が縞模様に波打って見える問題を直した。原因は2つとも
**ワールド空間の細かい模様が、遠くや浅い角度で1ピクセルより細かくなること**。
隣のピクセルが無関係な値を拾うので、少し動くだけで全部が入れ替わる。

- `ThermalSurface` の温度ムラ(16cmマス)とセンサーノイズ(2.5cmマス)に、
  **1ピクセルのワールド上の大きさ(`ddx/ddy`)で消えるフェード**を入れた。ミップマップと同じ考え方
- センサーノイズから**時間変化を外した**。VRで時間で動くノイズを入れると左右の目に
  別々のノイズが出て立体視が壊れ、ちらつきと酔いの直接の原因になる。
  実機のサーマルのざらつきは固定パターンノイズなので、止まっていても嘘ではない

> `EchoHighlight` は2点直した。
> 1. `fwidth` を上限なしで使っていたため、床や壁のように視線とほぼ平行な面で輪郭が発散し、
>    面いっぱいまで太ってベタ塗りになっていた。`_MaxEdgeUV`（既定0.05）で上限を掛けた。
> 2. 素のメッシュを使う大物向けに **`_UseObjectUv`（シェーダー側の箱投影）** と
>    **`_RimWeight`（シルエット輪郭）** を追加した。Read/Write が off のメッシュは
>    CPU側でUVを貼り直せないため。アヒルのような有機的な形は箱投影だけだと線が出ないので、
>    視線に対して縁になっている所を光らせる。反響定位で返るのは物の外形なので理屈にも合う。

## 1. PlayerVisionController（役割別の見え方）

`Main_Camera` にアタッチ済み。**設定済みなので基本さわらなくてよい。**

| フィールド | チェックするレイヤー | 背景 |
|---|---|---|
| echoCullingMask | Echo のみ | 真っ黒 |
| thermalCullingMask | Thermal のみ | 真っ黒 |
| memoryCullingMask | Default, Memory, Player, PlayerLocal | 通常(スカイボックス) |

`echoBlackout` / `thermalBlackout` がオンだと、スカイボックスを描かず真っ黒で塗りつぶす。
これで「暗闇の中に光る輪郭だけが浮かぶ」という見え方になる。

Echo/Thermalで **Player を外している** のが重要。他人の実アバターが消えて、代わりに
`RemotePlayerProxyManager` が出すマネキン(輪郭／熱源)が見える、という作りになっている。

※ VRChat実機ではシーンのCameraではなく `VRCCameraSettings.ScreenCamera` を書き換える実装。
　 `localCamera` はエディタ確認用なので未設定でよい。

## 1.2. EchoMaterial（輪郭の光り方）

`Assets/_BLIND/Art/Materials/EchoMaterial.mat`（シェーダー: `BLIND/EchoHighlight`）

エコロケ用メッシュにはこのマテリアルを使う。物体の面は真っ黒のまま、**UVの端（面の輪郭）だけが光る**。
パルスが当たっていない時は完全に真っ黒で見えない。

| プロパティ | 意味 |
|---|---|
| Edge Color | 輪郭の色（初期値は緑。白にしたければここを白に） |
| Edge Thickness | 輪郭線の太さ |
| Edge Intensity | 輪郭の明るさ |
| Glow Intensity | **さわらない。** `EchoReceiver` が0→1で自動制御する |

## 1.5. RemotePlayerProxyManager + HumanoidProxyRig（他プレイヤーの見え方）

PlayerVisionControllerでPlayerレイヤーを外しただけだと、Echo/Thermal役には**他プレイヤーが何も見えなくなる**。
代わりに主要な関節を追従する「人型プロキシ」を表示させることで、
「エコロケなら人型のシルエット」「サーマルなら人型の熱源」として相手の姿・ポーズが分かるようにする
(球体1個が浮いているだけではなく、しゃがむ/手を伸ばす等のポーズも再現される)。

### A. プレハブは作成済み(`Assets/_BLIND/Prefabs/HumanoidProxyRig.prefab`)

胴体・首・頭・両腕(上腕/前腕)・両脚(腿/すね) = 11パーツで構成済み。各パーツにEcho(23)用の輪郭メッシュとThermal(22)用の熱メッシュ(`ThermalHeat_Proxy.mat`)が重ねてあり、`HumanoidProxyRig`コンポーネントの配線(`torso`〜`rightShin`、`thermalRenderers`)も完了している。
太さ・見た目の微調整だけデザイン側で詰めてもらえればOK(位置・回転・長さは全部スクリプトが毎フレーム自動計算するので触らなくてよい)。

MainWorldシーンの `GameManagement` 以下に `Proxy_Slot0` / `Proxy_Slot1` として既に2体配置・`RemotePlayerProxyManager` への配線も完了済み。
p1マップ側でも同じプレハブを好きな場所に2体置いて `RemotePlayerProxyManager.proxyRigs` に入れれば動く。

### B. シーンに配置(p1側で使う場合)

1. `HumanoidProxyRig.prefab` を**自分以外の人数分**(最大2つ)シーンに置く
2. 空のGameObjectに `RemotePlayerProxyManager` をアタッチ(ワールドに常時1つ)
3. `proxyRigs` に配置したプレハブインスタンスを順番に入れる
4. `remotePlayerHeat` は熱の強さ(0〜1くらいで調整)

これで他プレイヤーの主要ボーン位置(頭/胸/腰/肩/肘/手/腰/膝/足)に毎フレーム自動で追従し、Echo役には輪郭だけ、Thermal役には熱だけが人型ポーズ付きで見える状態になる。
Memoryロールは元々Playerレイヤーを含めているので、他プレイヤーの実アバターがそのまま見える（プロキシは不要）。

## 2. CheckpointManager（セーブポイント）

空のGameObjectにアタッチ。

- `checkpoints[0]` = スタート地点のTransform
- `checkpoints[1]` = 赤ボタンの部屋
- `checkpoints[2]` = 青ボタンの部屋（レーザー）
- `checkpoints[3]` = 緑ボタンの部屋（最後の部屋）
- `doors` = 後述のToggleDoorを全部入れる

誰か1人が罠に触れると **全員** がここに戻る。

## 3. 赤・青・緑ボタン

**ShuffleSequenceManager**（空オブジェクト1個、マップに1つだけ）
- `shuffleManager` = ViewpointShuffleManager
- `checkpointManager` = 上のCheckpointManager
- `correctOrder` = 0, 1, 2（赤→青→緑）

**ShuffleButton**（ボタン3個それぞれに）
- `sequenceManager` = 上のShuffleSequenceManager
- `buttonId` = 赤:0 / 青:1 / 緑:2

押すと **視点シャッフル + セーブポイント登録 + 扉の開閉** が同時に起きる。

---

## 4. ToggleDoor（赤開く／赤閉じるドア）

扉ごとにアタッチ。

- `checkpointManager` = CheckpointManager
- `requiredCheckpoint` = 赤:1 / 青:2 / 緑:3
- `openWhenReached` = 「◯開くドア」なら **true** / 「◯閉じるドア」なら **false**
- `doorBody` = 閉じている時に置いておく板（Colliderつき）。開くとSetActive(false)される

状態は同期済みの `currentIndex` から計算するので、途中参加でもズレない。

---

## 5. QuizManager / QuizChoiceButton（クイズ部屋）

- `correctChoice` = 正解の選択肢番号（0始まり）
- `doorBody` = 正解で開く扉
- `trapFloor` = 不正解で消える床。**その下に落とし穴のHazardZoneを置く**
- `checkpointManager` = 床を使わず即セーブポイントに戻す場合のみ設定

選択肢ボタンごとに `QuizChoiceButton` を付けて `choiceIndex` を 0,1,2... と振る。
**問題文と選択肢のラベルはMemoryレイヤーに置く**（過去の人しか読めない）。

不正解後は再挑戦できる（ペナルティは落下と巻き戻しのみ）。完全に一回きりにすると詰むため。

---

## 6. PressurePlate / PressurePlateDoor（2つ踏むと開くドア）

**PressurePlate**（板ごと、IsTriggerのColliderが必要）
- `door` = 対応するPressurePlateDoor
- 板の見た目は **Echoレイヤー**（エコロケだけが形として認識できる）

**PressurePlateDoor**
- `plates` = 対応する板を全部
- `requiredCount` = 2
- `doorBody` = 扉の実体
- `stayOpen` = オフ推奨（降りたら閉まる。2人が踏み続けて1人が進む形になる）

同期変数を使っていないので設定漏れの心配はない。

---

## 7. HazardZone（落とし穴・レーザー）

- `checkpointManager` = CheckpointManager
- `thermalWarning` = DynamicThermalObject（サーモ役への警告表示）
- レーザーのように点滅させるなら `activeDuration` / `inactiveDuration` を設定

---

## 8. Sprinkler（スプリンクラー：サーモ＋エコロケ同時無効化）

天井などにIsTriggerのColliderを付けたゾーンとしてアタッチ。3人ぶん(視点コントローラ)ではなく、
**プレイヤーごとにこのスクリプトが動く必要がある**ので、プレイヤーローカルの仕組みに合わせて置く。

- `localVisionController` = 各自の `PlayerVisionController`（Main_Cameraのもの）
- `activeDuration` / `inactiveDuration` = 何秒水を撒くか／何秒休むか（初期値: 3秒/7秒）
- `blackoutDuration` = 作動中にゾーンへ入ると視界を奪う長さ（初期値: 3秒）
- `activeVisual` = 水しぶきなどの見た目（任意）

作動中にこのゾーンへ入ると、**エコロケ・サーモ役は一定時間、完全に真っ暗で何も見えなくなる**。
過去の人には効果がない(元々普通に見えているため)。全クライアントで`Time.timeSinceLevelLoad`基準の同じ周期になるので同期は不要。

---

## 9. 偽ボタン（PuzzleButton.isFake）

新規スクリプトではなく、既存の `PuzzleButton` に機能追加済み。本物のボタンと**見た目は同じ場所に並べて置く**。

- `isFake` = true にすると偽ボタンになる
- `memoryColorRenderer` = 過去の人だけに見えるMemoryレイヤーの装飾部分のRenderer
  → 指定すると自動で色分けされる（本物=`realColor`、偽物=`fakeColor`。初期値はほぼ同じ白系で、
    　よく見ないと気づかない微妙な違いにしてある。お好みで変更可）
- エコロケ・サーモからは本物と完全に同じ形・同じ熱にしか見えない（`memoryColorRenderer`をMemoryレイヤーに置くため）
- 押すと `LampPuzzleManager.OnFakeButtonPressed()` が呼ばれ、パズルが振り出しに戻る

## 10. マネキン部屋の「巨大な手」

新規ギミックスクリプトは不要。**当たり判定＋熱表現だけを持たせた、純粋に演出上の障害物**として置く（触れてもチェックポイント巻き戻し等のペナルティは発生しない）。

- 見た目のモデル: 既製アセットで一致するものがないため、Meshy.aiでの生成 or 手動モデリングを想定（要調達、[アセット棚卸しレポート](https://claude.ai/code/artifact/801d0e25-d744-436c-9163-06dd9c189217)参照）
- `Collider` を付けて物理的に道を塞ぐ
- 熱表現は既存の `DynamicThermalObject` をそのままアタッチすればよい（他の熱プロップと同じ使い方）
- 熱源の敵（人型・部屋中央から出て巡回）も同様に新規デザインのモデルは不要。既存の `WoodMannequin` ベースのシルエットを流用し、動きだけ新規のパトロール用UdonSharpスクリプトを別途書く想定（未着手）

## 12. 広告ポスター（マネキン部屋以外にも登場）

**方向性: 不気味で、どこか微妙にずれている感じ**（正常なポスターに見えるが、よく見ると違和感がある、くらいの塩梅）。

## 14. 床・壁・天井の質感を揃えるルール

複数のサイト(ambientCG／Sketchfab／Booth…)から寄せ集めると、解像度もPBRの作り方もバラバラで浮く。
そのため**床・壁・天井などの面材は基本的に ambientCG(CC0) に統一**し、取り込み手順も毎回同じにする。
小物(家具・雑貨)まで無理に統一する必要はない(そちらは「見た目が奇妙」を狙う雑多さがむしろ意図どおり)。

### 取り込みレシピ(実例: `Tiles141_White.mat`)

1. ambientCGの商品ページから **Color / NormalGL / Roughness の1K JPGセット**をダウンロード
   （NormalDXではなく**NormalGL**を使う。Unity(Built-in RP)はOpenGL規格の法線マップが正しい前提）
2. `Assets/_BLIND/Art/Textures/<アセット名>/` に3枚とも配置
3. NormalGL画像のTexture Type = **Normal Map** に変更
4. Roughness画像は sRGB を **オフ**（データ用テクスチャなので色空間補正しない）
5. マテリアルは **Standard シェーダー**で新規作成し、
   - Albedo = Colorテクスチャ、色は白(1,1,1,1)のまま(テクスチャの色をそのまま使う)
   - Normal Map = NormalGLテクスチャ
   - Metallic = **0固定**（床・壁・天井は基本非金属なので全部これで統一）
   - Smoothness = **手動スライダーで質感に近い値を入れる**（テカリ強め=0.6〜0.7、マットな床=0.2〜0.3程度）
     　→ Roughnessテクスチャをそのまま反転してSmoothnessチャンネルに焼き込む作業は手間がかかる割に効果が薄いため、
     　　今回は「スライダーで近似」に統一する。これなら全マテリアルが同じ手順・同じ見た目のブレ方になる。

この手順に沿って複製すれば、どのテクスチャを持ってきても最終的な質感(明るさ・光沢感・法線の効き方)が揃う。
テンプレートとして `Assets/_BLIND/Art/Materials/Tiles141_White.mat` を複製し、テクスチャだけ差し替えて使うのが最短。
